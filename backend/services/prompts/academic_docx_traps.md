

## ⛔ DOCX 渲染陷阱清单（写作时必须遵守，否则导出 Word 会走样）
**A. 代码块（附录代码最常踩坑）**
- 任何 ≥ 3 行的代码 **必须** 用 fenced 代码块包围：
  ````
  ```python
  import numpy as np
  ...
  ```
  ````
- ⛔ **绝不要** 把代码塞成一段普通正文（会全挤成一行）
- ⛔ **绝不要** 把多段代码用单反引号 `code` 行内格式串起来
- ```` ``` ```` 必须成对出现（开 + 闭都要写）
- 代码块内**不要**用 4 空格首行缩进（与 fenced 冲突）

**B. 公式与编号（最容易出问题）**
- ⛔ **绝对禁止：把 LaTeX 公式直接写在正文里不加 `$` 包裹**！例如：
  - ❌ `MA_t^{(k)} = \frac{1}{k}\sum P_{t-i} (1)` ← 错！会显示成原始字符乱码
  - ✅ 块公式（独占一行，最常用）：
    ```
    $$
    MA_t^{(k)} = \frac{1}{k}\sum_{i=0}^{k-1} P_{t-i}
    $$ (1)
    ```
  - ✅ 行内公式（嵌段落里）：`其中 $\sigma$ 为激活函数，$E=mc^2$ 是质能方程`
- ⛔ **每个公式各自独占一对 `$$`**：禁止连续多个公式塞进同一对 `$$` 里
  - ❌ `$$ f_1 = ... f_2 = ... f_3 = ... $$` ← 错！
  - ✅ 每个公式前后各加一对独立 `$$ ... $$`
- 块公式 `$$` 必须独占一行：开头一行只有 `$$`，结尾一行只有 `$$` 或 `$$ (n)`
- ⛔ **每个块公式都必须加编号**（论文规范要求），按文档顺序连续编号 (1)(2)(3)…：
  也可以用 `\tag{n}` 内嵌方式：`y = \alpha x \tag{2}` 写在 `$$...$$` 内
- 编号必须用半角括号 `(1)`，**不要** 用全角 `（1）` / `**(1)**` / `\quad (1)`
- 行内公式用 **单** `$` 包围：`$E=mc^2$`，绝不用 `$$E=mc^2$$` 在行内
- 中文紧贴 `$` 时记得加空格：`其中 $B$ 为...`（不是 `其中$B$为...`）
- 上下标用 `_` `^`，不要写 `<sub>` `<sup>` HTML 标签
- 不要写 `\begin{equation}`/`\begin{align}`（docx 引擎不解析 LaTeX 环境）
- 公式后紧跟正文时，**必须新起一段**：`$$...$$` 后空一行再写中文
  - ❌ `$$ f = ... $$ 其中 f 表示...` ← 错（公式和中文挤在一段）
  - ✅ 公式独占一段，下一段再写「其中 f 表示...」

**C. 三线表**
- 必须含**分隔行**：`|---|---|`
- 每行 `|` 数量必须一致（列数对齐）
- cell 内 `|` 必须转义为 `\|`
- 不要用 `<table>`/`<tr>`/`<td>` HTML 标签

**D. 图片**
- 只用 Markdown 语法：`![图 X：图题](figures/fig_xxx.png)`
- 不要用 `<img src=...>`
- 引用 `.png`，不要直接引用 `.pdf`（如确实只有 PDF，docx-precheck 会自动转）
- 图题（alt）建议带「图 X：」前缀

**D2. ⛔ 图题必须简短，禁止公式（这是 Word 模式比 PDF 模式更明显的失误）**

| 维度 | 限制 | 例子 |
|---|---|---|
| 长度 | ≤ 15 个中文字符 / ≤ 10 个英文词 | ✅ `残差诊断四联图` ❌ `Wiener 过程模型残差诊断。(a) Q-Q 图...(b) 残差 vs 拟合值...` |
| 公式 | **禁止** 在图题里用 `$...$` 行内公式 | ❌ `图 4-11 单帧质量 $Q_t$ 序列与时序因子修正后的视频综合质量 $Q_{video}$`<br>✅ `图 4-11 单帧与视频综合质量对比` |
| 详细说明 | 移到正文（图前 1-2 句引导 + 图后 3-5 句解读） | 图题只是标签，不是文档说明 |
| 标点 | 编号和标题用空格分隔，不用冒号 | ✅ `图 4-11 残差诊断` ❌ `图 4-11：残差诊断` |

**为什么 Markdown 模式特别敏感？**
LaTeX 的 `\caption{}` 会自动渲染 `$Q_t$` 为公式（PDF 能看见 Q 下标 t）；但 Word 引擎对图题（alt 文字）走纯文本路径，
`$Q_t$` 会**原样显示成 `$Q_t$` 字符串**。所以图题里**绝对不要写公式**——把变量描述移到正文：

- ❌ `![图 4-11 单帧质量 $Q_t$ 序列与时序因子修正后的视频综合质量 $Q_{video}$](figures/fig.png)` ← 又长又含公式
- ✅ `![图 4-11 单帧与视频综合质量对比](figures/fig.png)` 然后正文：「图 4-11 给出单帧质量 $Q_t$ 与视频综合质量 $Q_{video}$ 的对比……」

**E. Markdown 噪声（避免）**
- 不要整段 `**加粗**`
- 不要写 `<div>`/`<span>`/`<p>` 等 HTML 块
- 不要保留转义的双反斜杠 `\\`（LaTeX 公式中除外）
- 不要混入 `&nbsp;`/`&amp;` 等 HTML 实体

**F. 标签 + 冒号 + 内容 的写法（关键词/问题/研究目标 等都遵守）**
凡是「**标签**：内容」的写法，**冒号必须在 `**` 外面**，不要把冒号包进加粗里：
- ❌ `**关键词：** AI 生成图像质量评价；...` ← 冒号在 `**` 内，docx 引擎正则识别失败 → Word 里残留 `**`
- ✅ `**关键词**：AI 生成图像质量评价；...` ← 标签和冒号分开
- ❌ `**问题一：** 针对 AI 生成图像，建立...`
- ✅ `**问题一**：针对 AI 生成图像，建立...`
- ❌ `**研究目标：** 提出无参考综合质量评估指标体系`
- ✅ `**研究目标**：提出无参考综合质量评估指标体系`

把冒号写进 `**` 内是中文 AI 写作最高频的痕迹之一，渲染到 Word 后会留下两颗孤立 `*`（视觉上像 `**` 字符），非常 AI。


**写完后强制自检**：用 Bash 工具运行下列检查，发现问题立即用 Edit 工具修复
（替换 `{{ target_md }}` 为你写的目标文件，如 `paper/main.md` / `PROPOSAL.md`）：
```bash
TARGET={{ target_md }}
n=$(grep -c '^```' "$TARGET" 2>/dev/null || echo 0)
[ $((n % 2)) -ne 0 ] && echo "❌ 代码块标记不平衡（共 $n 个）"
grep -nE '\$\$\s*[（][0-9]+[）]' "$TARGET" && echo '⚠ 公式编号用了全角括号'
grep -nE '<img\s' "$TARGET" && echo '⚠ 出现 HTML img 标签'
grep -nE '<(div|span|table|tr|td)\b' "$TARGET" && echo '⚠ 出现 HTML 标签'
# F 段：标签里把冒号包进加粗里（**xxx：** 形式）
grep -nE '\*\*[^*]+[：:]\*\*' "$TARGET" && echo '⚠ 检测到 **标签：** 写法（冒号在加粗里），改成 **标签**：'
```
**问题必须就地修复，不要让它流到 docx-format-check / docx-export 步骤。**
